## 1. 项目目标

面向 NAS 售后客服，将收到的客户邮件转换为可编辑、可追溯的回复草稿，并由人工决定批准、修改、拒绝或转人工。

第一版使用 API 或本地样例模拟收件，通过检索增强生成（RAG）查找历史案例和产品文档；审核通过后仅模拟发件并保存记录，不读取或发送真实邮件。

```text
模拟收件
  → 分类与条件路由
  → 检索、证据评估与必要的查询改写
  → 生成和有上限的质量校验循环
  → 人工审核 interrupt
  → 模拟发件或转人工
```

## 2. 目标用户与输入输出

- **目标用户**：NAS 售后客服。
- **输入**：仅包含主题和正文的模拟客户邮件。
- **输出**：
  - 邮件分类、优先级和风险建议；
  - 带知识来源的回复草稿；
  - 依据不足、资料冲突或操作风险提示；
  - 人工审核结果和模拟发件记录。

## 3. 第一版必须实现

- 通过页面或 API 模拟接收邮件并保存原文。
- 让所有邮件进入统一的 Agent 处理流程。
- 同时检索历史邮件与已审核回复、NAS 产品与排障文档。
- 基于检索依据生成可编辑、可追溯的回复草稿。
- 检索不相关时在次数上限内重写查询并再次检索。
- 生成结果缺少证据或未通过质量校验时补充检索、重新生成或转人工，所有循环必须有上限。
- 根据垃圾邮件、VIP 投诉、常见问题和信息不足等结果执行明确的条件路由；低置信度分类进入人工路径。
- 使用 PostgreSQL Checkpointer 保存 Graph 状态，并通过 interrupt 暂停和恢复人工审核。
- 展示原始邮件、分类、优先级、风险、引用依据和回复草稿。
- 支持批准、编辑后批准、拒绝和转人工。
- 审核通过后模拟发送并保存记录，不产生真实外部副作用。
- 防止重复收件、重复审核和重复模拟发送。
- 保存从收件、检索、生成、审核到模拟发件的审计记录。
- 知识不足、资料冲突或风险较高时，只生成说明不足、请求补充信息或建议人工处理的草稿。

## 4. NAS 售后业务范围

### 4.1 问题分类

- 设备离线与无法启动；
- 硬盘、存储空间与存储池异常；
- 局域网或远程访问异常；
- 账号、权限与共享目录；
- 文件同步与备份；
- 相册、媒体与应用服务；
- 产品使用咨询；
- 其他或无法判断。

### 4.2 优先级建议

| 优先级 | 判定示例 |
| --- | --- |
| `urgent` | 数据疑似丢失、存储池损坏、多盘异常、安全入侵 |
| `high` | NAS 无法启动、完全离线、核心数据无法访问 |
| `normal` | 单项服务不可用、同步失败、权限异常 |
| `low` | 使用咨询、功能建议、非阻塞问题 |

优先级只是 Agent 建议，人工审核时可以修改。

### 4.3 风险边界

出现以下情况时，Agent 不得给出确定性的危险操作步骤：

- 删除数据、格式化、初始化或重建存储池；
- 硬盘故障、阵列降级或数据丢失风险；
- 修改公网暴露、管理员权限或安全配置；
- 执行可能覆盖数据的命令；
- 检索不到可靠依据；
- 邮件信息不足或检索资料相互冲突。

所有 Agent 输出均须人工审核。相似度或模型自报置信度不能代替人工判断。

## 5. 第一版不做

- 读取真实邮箱，或实现 IMAP、SMTP、OAuth 和供应商邮箱 API。
- 发送真实邮件。
- 创建或对接工单。
- 处理保修、维修、退换货和物流。
- 解析附件。
- 支持多租户或多 Agent。
- 允许模型自主执行外部操作。

## 6. 业务验收场景

准备固定、版本化的 NAS 售后邮件集，至少覆盖：

| 场景 | 预期结果 |
| --- | --- |
| 产品文档和历史案例均匹配 | 生成带产品事实依据和合适表达样板的草稿 |
| 只匹配历史案例 | 不把历史案例当作产品事实依据 |
| 邮件信息不足 | 请求补充必要信息，不输出确定性解决步骤 |
| 完全超出知识库 | 说明没有可靠依据并建议人工处理 |
| 检索资料相互冲突 | 提示资料冲突，不选择未经确认的结论 |
| 数据丢失或存储池损坏风险 | 突出风险，不输出格式化、重建或删除指令 |
| 重复提交 | 不产生重复邮件或模拟发件记录 |
| 邮件包含提示注入内容 | 邮件正文不能改变系统规则和引用要求 |
| 模型超时或返回非法结果 | 进入人工处理，并保留失败记录 |
| 人工编辑、拒绝或转人工 | 正确保存最终内容、审核动作和原因 |
| 首次检索不相关 | 重写查询并再次检索，不超过配置的循环上限 |
| 生成质量校验失败 | 在上限内重新生成，达到上限后转人工 |
| 人工审核期间服务重启 | 从持久化 checkpoint 恢复同一待审核流程 |
| 重复恢复或节点重放 | 不产生重复审核、模拟发件或候选案例 |

## 7. MVP 完成标准

1. 所有模拟邮件均经过 Agent 流程，并最终进入可审核或人工处理状态。
2. 没有产品事实依据时，不输出确定性的解决方案。
3. 回复中的关键事实具有可追溯且能够支持结论的引用。
4. 高风险邮件不包含格式化、重建、删除等危险操作指令。
5. 所有 Agent 输出均需人工确认，系统不会读取或发送真实邮件。
6. 重复收件、重复审核和重复模拟发送不会产生重复记录。
7. 每次状态变化、模型运行、引用选择和人工操作均可审计。
8. 固定评测集能够比较 Prompt、嵌入模型或检索策略调整前后的结果。
9. 条件路由、查询改写、证据评估、生成校验和有限循环均可通过 Graph 路径测试验证。
10. 人工审核可以中断并恢复；服务重启后从最近成功 checkpoint 继续，未完成节点重放时仍保持业务幂等。
