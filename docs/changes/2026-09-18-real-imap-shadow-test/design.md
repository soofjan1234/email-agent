# 正式 IMAP 只读盘点与模拟处理设计

## 结论

直接以正式邮箱中配置的 Inbox 和 Sent 文件夹作为历史来源，不建立专用测试文件夹，也不按 2026-08-01 或其他日期拆分数据。系统使用隔离数据库保存处理结果；已回复邮件用于收发关系和人工审核候选，明确未回复邮件按现有工作流生成草稿或进入人工路径。任何发送均维持模拟发件箱，不调用 SMTP。

## 当前事实与约束

- IMAPMailboxAdapter 使用只读 SELECT、UID 搜索和 BODY.PEEK[]；不会写入源邮箱。
- MailSyncService.run_history 会捕获配置 Inbox 与 Sent 的完整快照，识别确定收发配对，并为配对生成待审核候选。
- 历史初始化完成后，project_unmatched_history 会将明确未配对的 Inbox 邮件投影为业务邮件；worker 按既有工作流处理它们。此副作用为本主题接受的现有行为，业务数据必须留在隔离数据库。
- 当前实现没有基于日期筛选历史初始化的入口；取消日期分界与现有实现一致。

## 数据流与统计口径

1. worker 对正式 Inbox 和 Sent 创建不可变历史快照并记录 UID 初始化边界。
2. 系统解析快照、识别确定的一对一收发关系，并保留未配对、复杂关联或解析失败的原因。
3. 人工确认确定配对；审核候选时填写产品、适用条件、风险标签和售后问题分类。只有审核发布的候选可成为检索知识。
4. 报告将 scanned_count 作为读取的源邮件总数，单列 paired_count、candidate_count、unsupported_count 和原因。主要售后问题按人工已分类候选汇总，并同时记录分类分母、未分类及未审核数量。

scanned_count 包含 Inbox 与 Sent 两个来源，不能直接解释为客户来信数；配对数量也不代表所有历史对话的数量。报告必须保留这些边界。

## 配置与安全边界

.env 中的 IMAP_MAILBOX_FOLDER 与 IMAP_SENT_FOLDER 填写正式邮箱的实际 IMAP 路径，例如 INBOX 和服务商返回的 Sent 路径。MAILBOX_ID 使用本主题独立值，业务库和 _test 库必须新建并相互独立。

若 IMAP 登录、只读文件夹选择、数据库隔离、Embedding 或生成服务检查失败，停止 worker 并记录失败；不得回退到模拟邮箱伪造盘点结果。生成服务不可用时，既有工作流必须安全转人工，不得发送真实邮件。

## 不再成立的结论

- 不存在“8 月前知识库、8 月后 Agent 对照集”的数据隔离。
- 无法以本主题证明 Agent 未见人工答案，也不能报告基于该前提的检索、草稿对照或时延指标。
- 正式邮箱历史被写入隔离测试库是用户接受的处理范围，隔离数据库仍用于避免污染其他主题。

## 验证证据

每次实际运行在 validation.md 记录时间窗、匿名邮箱标识、实际 IMAP 路径、模型身份、命令、统计结果和限制。报告不得记录凭据、完整正文或客户身份信息。当前尚未连接 worker 或读取正式邮件。
